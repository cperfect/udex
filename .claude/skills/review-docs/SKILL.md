Scope: $ARGUMENTS

Review documentation, not code. Resolve the scope as follows:
- No argument, not on `main` → docs changed on the current branch vs `main`
- No argument, on `main` → docs touched by the current HEAD commit
- `*` → all docs in the project
- A PR number (`123` or `#123`) → docs in that PR's changeset vs its base
- A branch name → docs changed by that branch vs `main`
- A commit SHA or ref → docs touched by that commit
- A file path or glob → restrict the default scope to matching files only

Always exclude from every scope above:
- **Git-ignored docs** — never review a file that `git check-ignore -q <path>` matches
  (e.g. generated or vendored docs). For the `*` scope, enumerate via
  `git ls-files --cached --others --exclude-standard`, which already respects `.gitignore`.
- **The `intent/` directory** — Intent-managed tracking docs (steel threads, work packages,
  LLM guidelines) are out of scope; drop any path under `intent/`.
- **Claude-specific docs** — any `CLAUDE.md` (at any depth) and everything under a `.claude/`
  directory (skills, agents, settings) are out of scope; drop those paths.
- **Intent-generated root docs** — `AGENTS.md` and `usage-rules.md` are regenerated by the
  Intent CLI (`intent agents sync` / `mix usage_rules.sync`); they are out of scope.
- **`docs/META.md`** — out of scope per project directive; drop this path.

The doc-reviewer agent holds the review guidance (accuracy, staleness, links, placement,
and convention rules sourced from CONTRIBUTING.md `#### Docs`). Summarize its findings,
then offer to work through them one by one.

When working through a finding, recommend a fix and give three options: a) Apply the fix,
b) Think again (I will provide more input), or c) leave but add an appropriate note (e.g. a
`TODO`) and move on. Fixes should include appropriate notes/links where helpful.

After each finding has been worked through, offer to create a commit.
