# RFC 2119 — Key Words for Use in RFCs to Indicate Requirement Levels

Source: https://www.ietf.org/rfc/rfc2119.txt (March 1997, Scott Bradner, Harvard University)

These keywords are used normatively in Udex development guides. Interpret them as defined below.

| Keyword(s) | Meaning |
|---|---|
| **MUST** / **REQUIRED** / **SHALL** | Absolute requirement. No exceptions. |
| **MUST NOT** / **SHALL NOT** | Absolute prohibition. No exceptions. |
| **SHOULD** / **RECOMMENDED** | Preferred behaviour. May be bypassed only when the implications are fully understood and a deliberate decision is made. |
| **SHOULD NOT** / **NOT RECOMMENDED** | Behaviour to avoid unless carefully justified by specific circumstances. |
| **MAY** / **OPTIONAL** | Truly optional. Implementations that omit it must still interoperate with those that include it. |

> These imperatives should be used only where necessary for interoperability or safety. Security implications must be documented carefully.
