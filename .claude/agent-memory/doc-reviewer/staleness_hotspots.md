Recurring drift points in Udex docs — verify against source, don't trust prose:

- Version pins must agree across: `.devcontainer/Dockerfile` (RUST_VERSION 1.95.0), `.devcontainer/devcontainer.json` (protoc v34.1), `projects/compose/docker-compose.yml` (postgres:16, oryd/hydra:v26.2.0, openobserve v0.92.0, otelcol-contrib 0.119.0, vector 0.44.0), `.devcontainer/post-create.sh` (HYDRA_VERSION), `scripts/dev-doctor.sh` (`REQUIRED_OPENOBSERVE_MAJOR`). Docs referencing these: README, .devcontainer/README, projects/rust/CONTRIBUTING (canonical table), compose/README, k8s/README, server/README.

The following drifted previously and were FIXED in the docs-tidy pass — re-verify here if they regress:

- Postgres image in test examples: `datastore/README` now uses `postgres:16-alpine` (was `postgres:13-alpine`, which contradicted the 16+ requirement). Confirm it stays aligned with `compose/docker-compose.yml` (postgres:16).
- Proto count: `protobuf/README` now says "both files" (was "all three .proto files"). Only 2 protos exist: udex.index.v1, udex.entry.v1 (a healthz proto was removed).
- Hydra-test skip behaviour: project rule (CLAUDE.md) = Hydra tests MUST NEVER skip; source `jwks_refresh_tests.rs` fails hard. `server/README` now says "fail hard, never skipped" (was "skip gracefully"). (Distinct from k8s tests which DO early-return when K8S_SERVER_URL unset — that's intended.)
- Test naming: canonical prefixes are layer indicators (test_sdk_, test_server_, test_index_service_, test_entry_service_, test_datastore_, test_cli_, +_oauth2_/_k8s_ variants). No `test_hydra_` prefix exists; `server/README` now references the `_oauth2_` infix (was claiming `test_hydra_`).
- Generated-by HTML comments (`<!-- Generated by Claude Code ... -->`) were removed from the rust crate READMEs (api/datastore/server/cli) as AI-artefact noise. Re-flag if they reappear.

Observability facts — the backend has now changed TWICE (ST0026 Grafana stack → ST0027 ClickHouse+HyperDX+Mongo → ST0028 OpenObserve). Assume any observability prose older than the current branch is stale; verify against source:
- `TelemetryConfig` fields (`projects/rust/telemetry/src/config.rs`): enabled, otlp_endpoint, otlp_ca, sample_ratio, traces, metrics, logs, resource_attributes.
- `init` signature (`telemetry/src/lib.rs`): `init(&TelemetryConfig, ServiceIdentity) -> Result<TelemetryGuard, TelemetryError>` — returns Result; docs dropping it are wrong.
- Metric instruments: `udex.rpc.requests` (counter) + `udex.rpc.duration` (histogram). OpenObserve makes one stream per metric with dots→underscores (`udex_rpc_requests`); histograms split into `_bucket`/`_count`/`_sum`/`_min`/`_max`.
- There is NO `projects/observability/` directory — the fixture lives inside `projects/compose/docker-compose.yml` (services: openobserve, otel-collector, vector). Docs pointing at `projects/observability/` are stale.
- ST0028 fixture facts: OpenObserve `public.ecr.aws/zinclabs/openobserve:v0.92.0` on `127.0.0.1:5080` (UI + `_search` API + OTLP ingest); no healthcheck (distroless) so dependents use `service_started`; collector `otel/opentelemetry-collector-contrib:0.119.0` (4317/4318 + 13133 health); `timberio/vector:0.44.0-debian` now emits OTLP to the collector (no longer writes to the store directly).
- Attribute-flattening asymmetry (`sdk/tests/common/mod.rs`, `obs.rs`): resource attributes get a `service_` prefix in the traces stream, bare in logs/metrics. Traces+logs land in stream `default`.
- The container-log floor is NOT durable against a collector outage since ST0028 — Vector routes through the collector rather than writing to the store. Only the server's own JSON-on-stdout is a durable floor. Docs calling the Vector path "durable" are stale (this exact claim survived the ST0028 rewrite and had to be caught in review).
- "Only the collector knows the backend" is a claim about the *telemetry pipeline* only. `sdk/tests/common/mod.rs`, `scripts/gen-env.sh`, `scripts/dev-doctor.sh` and `.github/workflows/01-Validation.yml` all name OpenObserve directly. Docs asserting a backend swap touches "docker-compose.yml and nothing else" are overstating it.
- Credential/login instructions belong in `projects/compose/README.md#observability` ONLY; `.devcontainer/README.md` and `projects/k8s/README.md` must link, not repeat. The pre-ST0028 HyperDX credentials drifted precisely because they were copied into all three.
- Credentials from `scripts/gen-env.sh`: `OPENOBSERVE_ROOT_EMAIL` (root@udex.local), `OPENOBSERVE_ROOT_PASSWORD_SECRET` (`Ux1-` + hex, OpenObserve panics on a hex-only password), derived `OPENOBSERVE_BASIC_AUTH_SECRET`, plus public `OPENOBSERVE_URL` (host default `http://localhost:5080`; `post-create.sh` exports `http://openobserve:5080` for the devcontainer; CI uses localhost).
- Test names: non-k8s `obs_*` in `sdk/tests/obs.rs` (obs_search_surfaces_query_errors, obs_container_log_floor_lands, obs_postgres_receiver_metric_lands, obs_local_traces_metrics_logs_land); k8s `test_obs_k8s_{traces,metrics,logs}_land` in `integration_tests.rs`, which early-return when `K8S_SERVER_URL` is unset.
- k3d: `observability.otlpEndpoint: http://host.k3d.internal:4317` + `dangerousAllowNonTls: true`, `deploymentEnvironment: k3d` (`projects/k8s/helm/udex/values.yaml`). Plaintext — no OTLP CA mount any more.
- `scripts/dev-doctor.sh` pins OpenObserve to major `0` (REQUIRED_OPENOBSERVE_MAJOR) but the pinned-version table in `projects/rust/CONTRIBUTING.md` lists only Rust/protoc/Hydra/PostgreSQL — recurring gap between doctor pins and the documented table.
