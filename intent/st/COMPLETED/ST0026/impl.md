# Implementation - ST0026: Open Observability

## Implementation

End-to-end OpenTelemetry observability for the Udex server-side, delivered across
seven work packages. The application is coupled only to the open OTLP standard; a
local Grafana stack provides the dev backends.

### As-built component map

- **`projects/observability/`** (WP01) - opt-in local stack: OTel Collector
  (contrib, with `postgresqlreceiver`), Tempo, Prometheus, Loki, Vector, Grafana.
  `up.sh`/`down.sh`/`rebuild.sh` run it as its own compose project attached to the
  running base/devcontainer network. OTLP TLS certs generated by
  `certs/regenerate_certs.sh` (folded into `gen-keys-and-certs.sh`); Grafana
  credential from `gen-env.sh`.
- **`udex-telemetry` crate** (WP02) - the only crate that sets up an OTel
  provider/exporter. `init(&TelemetryConfig, ServiceIdentity) -> TelemetryGuard`
  builds the combined `tracing-subscriber` (always-on JSON stdout + optional OTLP
  traces/metrics/logs), installs global providers + the W3C propagator, flushes on
  drop. Also exposes `make_request_span` + `record_request` for the server
  middleware. OTLP over gRPC with TLS (custom CA via tonic 0.14).
- **Server** (WP02/WP03) - `observability` config section threaded from the CLI
  config; `serve()` calls `udex_telemetry::init`. Cross-cutting middleware (a
  tower `MetricsLayer` + `TraceLayer.make_span_with(make_request_span)`) gives
  per-request spans, per-method metrics, and inbound `traceparent` continuation
  without touching the handlers (Thin Coordinator).
- **Datastore** (WP03) - `#[instrument(name = "db.<op>")]` on the 12 `Datastore`
  impl methods -> query spans nested under the request span.
- **SDK** (WP04) - provider-free: `#[instrument]` `sdk.*` client spans + the auth
  interceptor injects the ambient context as `traceparent`. Uses the
  `opentelemetry` API only; the host owns the provider. The CLI opts into
  telemetry via `UDEX_OTLP_ENDPOINT`.
- **K8s** (WP05) - chart `observability` block enabled with full sampling; pods
  export OTLP to the local-stack Collector via `host.k3d.internal:4317` (no
  in-cluster Collector); OTLP CA mounted from the Secret; cluster telemetry tagged
  `deployment.environment=k3d`.
- **Tests** (WP06) - `test_obs_k8s_*` assert traces/metrics/logs land by querying
  Tempo/Prometheus/Loki; idempotent (unique entry key per run) with clean skip.
- **Docs** (WP07) - ARCHITECTURE.md Observability section + diagram, SECRETS.md,
  CONTRIBUTING test-naming, k8s/compose READMEs, telemetry crate README.

## Key design decisions

- **Open-standard boundary**: provider/exporter setup confined to `udex-telemetry`;
  the SDK uses the `opentelemetry` API but never installs a provider (host-owned).
- **Logs are hybrid**: OTLP when an endpoint is set, always JSON to stdout as a
  durable floor (shipped by Vector).
- **Metrics push** via OTLP (no extra app listener; server stays single-port
  TLS-gRPC).
- **TLS on OTLP** throughout (generated CA, gitignored), consistent with the
  project's TLS-everywhere principle.
- **K8s reuses the local stack** (pods -> host.k3d.internal:4317) rather than a
  duplicate in-cluster Collector.
- **Cross-cutting instrumentation in middleware**, handlers untouched.

## Post-completion changes

- **Observability stack default-on in the devcontainer** (follow-up to WP01's
  opt-in decision): `.devcontainer/post-create.sh` now runs
  `projects/observability/scripts/up.sh` (non-fatal) after first-time setup, so the
  Collector/Tempo/Prometheus/Loki/Grafana/Vector components are up by default in
  the devcontainer (with `restart: unless-stopped` carrying across restarts). It is
  still opt-in outside the devcontainer (plain `docker compose up` is unchanged),
  and **application/SDK telemetry export remains opt-in** (server config /
  `UDEX_OTLP_ENDPOINT`), so test runs are unaffected. The stack is run via `up.sh`
  rather than merged into the devcontainer compose file set, to keep the WP01
  host-path-translation and external-network handling intact.

## Challenges & Solutions

- **docker-outside-of-docker bind mounts** (WP01): the host daemon does not know
  the in-container `/workspace` path, so it created empty dirs and every config
  file mounted as a directory. Fixed by translating bind-mount sources to host
  paths via `OBS_HOST_DIR` (the devcontainer's `/workspace` mount source).
- **Multi-file compose relative paths** (WP01): `-f a -f b` resolves relative
  mounts against the first file's dir. Avoided by running observability as its own
  single-file project on the detected external network.
- **OTel-Rust version churn** (WP02): settled on the 0.32 line; OTLP gRPC needs
  tonic 0.14 (a second tonic alongside the app's 0.13, used only to build the
  client TLS config).
- **Shared global tracing subscriber** (WP06): in-process telemetry tests would
  fight the one-subscriber-per-binary rule, so the obs tests drive the k3d
  deployment (which exports its own telemetry) and tag by the unique server-
  generated entry key - no host telemetry in the test process.
- **Chart `required` vs the k8s test harness** (WP05): making `secrets.otlpCa`
  required broke the integration test's `redeploy_k8s_server`; fixed by passing
  the OTLP CA there too.
- **OTLP cert SAN** (WP05): added `host.k3d.internal` so pods verify the
  Collector cert.
