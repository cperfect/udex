# Design - ST0024: K8s ingress TLS termination

## Approach

Swap the Traefik ingress from L4 TCP passthrough to L7 HTTP TLS termination, re-encrypting to the pod so no server (Rust) change is needed. Deliver a statically generated edge certificate (with its own CA) from `projects/k8s/traefik/certs/`, generated by a new script wired into the top-level cert generation.

## Architecture

```text
Client (SDK/CLI)
  │  HTTPS / gRPC (HTTP/2), verifies EDGE cert (traefik CA)
  ▼
k3d load balancer  host:8443 → :443
  ▼
Traefik (websecure entrypoint, L7)
  │  ── terminates client TLS with the static EDGE cert ──
  │  IngressRoute (kind: IngressRoute, not IngressRouteTCP)
  ▼
  │  re-encrypt: NEW TLS h2 via ServersTransport (scheme: https)
  ▼
Service :443  ──►  Pod :443  (udex-server terminates its OWN TLS, cert unchanged)
```

The only L4→L7 swap is at Traefik: `IngressRouteTCP` + `tls.passthrough` is replaced by an `IngressRoute` that terminates TLS plus a `ServersTransport` that re-encrypts to the backend. The Service, Deployment, ConfigMap, and the pod's own TLS are unchanged.

## Design Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | Re-encrypt Traefik→pod (not plaintext h2c) | Server TLS is mandatory (`server.rs:179`, `config.rs:18,107-127`); no Rust server change. Keeps TLS-everywhere. |
| D2 | Edge cert gets its **own CA** under `projects/k8s/traefik/certs/` | Self-contained cert domain; mirrors how `server/tests/certs` owns its CA. Per user, test-code change to trust it is acceptable. |
| D3 | Edge cert SANs: `host.docker.internal`, `localhost`, `127.0.0.1`, `::1` | Client verifies hostname from `K8S_SERVER_URL` (default `host.docker.internal`); CI uses `localhost`. |
| D4 | `ServersTransport.insecureSkipVerify: true` for the backend hop | Traefik connects to the pod by Service name / pod IP, which won't match the pod cert SANs. Simplest for local dev. Hardening alternative below. |
| D5 | Edge cert delivered as a `kubernetes.io/tls` Secret, referenced by `IngressRoute.tls.secretName` | Standard Traefik pattern for a static per-route cert. |

## Cert generation

New script `projects/k8s/traefik/certs/regenerate_certs.sh`, modelled on `projects/rust/server/tests/certs/regenerate_certs.sh`:

- Generates `ca.key`, `ca.crt` (self-signed edge CA), `tls.key`, `tls.crt` (edge cert signed by that CA).
- SANs per D3.
- `chmod 600 *.key`, `644 *.crt`.
- Idempotent clean of prior artifacts; clear "dev only" banner.
- Files are gitignored (same posture as the existing test certs).

Wire into `scripts/gen-keys-and-certs.sh`:

- Add a `==> Generating Traefik edge TLS certificates...` step calling the new script.
- Add the four new files to the `ALL_EXIST` guard list so a partial state triggers regeneration.

## Alternatives Considered

- **Plaintext h2c to the pod (rejected).** The "true" edge-termination model, but the server cannot serve plaintext (TLS is unconditional). Would require making `TlsConfig` optional + a conditional `tls_config` + a new insecure listen mode (~30–50 lines across `config.rs`/`server.rs`/`cli/config.rs` + new test fixtures) — a deliberate insecure-mode design decision against the project's TLS-everywhere posture. User chose re-encrypt instead.
- **Reuse the existing dev CA for the edge cert (rejected).** Would avoid any test change, but couples the k8s cert domain to `server/tests/certs`. User opted for a self-contained CA with the test repointed.
- **D4 hardening — `rootCAsSecrets` + `serverName` instead of `insecureSkipVerify` (deferred to prod).** Requires a stable internal SAN on the pod cert. Local dev uses `insecureSkipVerify`.

## Risks / watch-items

- **Trivy / KSV misconfig scan.** Recent commits render the Helm chart for Trivy. `insecureSkipVerify: true` and the new TLS Secret may trip findings — check the scan and add a justified, annotated suppression if needed (consistent with the existing "dormant KSV suppressions" approach).
- **gRPC over re-encrypt.** Traefik must speak h2 to the backend; with `scheme: https` it negotiates HTTP/2 via ALPN. Verify end-to-end with the k8s integration test.
- **CRD availability.** `IngressRoute` and `ServersTransport` CRDs ship with k3d's Traefik (same as `IngressRouteTCP`), but the readiness poll in `cluster-create.sh` must target the new CRD names or deploy can race.
- **Two cert lifecycles.** Edge cert (`traefik/certs`) and pod cert (`server/tests/certs`) now both exist; `--force` regeneration and dev-doctor must cover both.

## Validation

1. `bash scripts/gen-keys-and-certs.sh --force` → edge CA + cert generated.
2. `bash scripts/validate-lint-helm.sh` → chart lints with new templates.
3. `cluster-create → image-build → image-load → deploy` → rollout succeeds; IngressRoute + ServersTransport applied.
4. `bash scripts/validate-k8s-test.sh` → `test_sdk_k8s_*` pass against the re-encrypting ingress.
5. `bash scripts/dev-doctor.sh` → reports edge cert material present.
